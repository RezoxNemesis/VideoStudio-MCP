# Native animation owner workspace — source implementation

This checkpoint adds actual authoring controls to the anchored-preview editor. It is source implementation only. No build, test, parser, emulator, CI, or rendered output verification was executed during this implementation phase.

## Shared graph and concurrency

The Animation tab uses the same `ProjectStore.edit(projectId, expectedRevision, ...)` transactions and pure helper mutations as the native MCP path. Dialogs capture the project ID and revision when opened. Stale dialogs cannot silently write their earlier values into a newer graph. Graph commits retain undo/redo and track-lock validation. Preview selections and draft handle movements do not produce graph revisions; a released handle commits once.

## Articulated still-image rigs

`EditorRig2DInspector` exposes a default body rig, custom connected two-bone setup, adding/reparenting/removing bind bones, local rotation/translation/squash/stretch pose keys, visible-window bone keys, reusable pose capture/application, existing-clip rig reuse, automatic or per-vertex weights, and connected two-link IK targets and keys. `AnimationRigEdits` performs the mutations; `AnimationRig2D` validates and compiles the weighted image mesh and samples FK/IK on the retained authored clock.

`EditorRig2DView` shows sampled joints, IK targets and weighted mesh over the programme preview. Paused joint taps select bones. Bind mode drags rest endpoints with explicit connected-joint preservation while retaining painted weights. Pose mode drags an IK target and stores a target key at the current authored time. Vertex taps open the actual influences for that vertex. FK numeric pose keys expose all five supported channels. The curve widget uses the rig's actual named easing evaluator, including its quadratic ease-in/out, and the shared X-solved cubic Bézier solver.

The overlay maps source UV through fit/cover into the programme canvas, then through the sampled clip motion matrix. Weight geometry follows the renderer's transformed source-frame clipping; off-image bone/IK controls remain visible for authoring. Direct source handles are withheld for authored crop, reframe, procedural/title overlays and effect-stack transforms whose coordinate mapping this overlay does not represent. Disabled rigs do not imply a rendered mesh. The current articulated source is a registered still image, including a drawn cel; this is whole-image deformation, without automatic segmentation or character-part extraction. Connected IK requires unit scales and zero child translation; the shared helper admits the actual constraints and bounds, rather than saving an unusable pose.

## Sparse rig dope sheet

The Animation panel embeds `EditorAnimationDopeSheet` while retaining the programme monitor above it. Actual sparse keys are grouped by bone and IK chain, with expandable rotation/local X/local Y/stretch or target X/target Y/mix lanes. Diamonds exist only for channels present in the persisted row. Label taps select and expand groups; key taps select and seek. The lanes support horizontal/vertical panning, pinch zoom and Fit. The selected lane, key and viewport survive the owner's graph rebuilds.

The normal ruler uses clip-local seconds; Whole authored clock reveals retained keys outside a trimmed clip. Details show exact authored milliseconds, signed animation offset, sparse values, easing and revision. Off-window keys can be edited on their retained authored clock but cannot claim an in-program seek. Extended trim regions that hold the nearest authored state reject new keys outside the authored window. Dope-sheet lane selection and viewport are in-memory owner state across graph redraws; they are not restored after Activity/process recreation.

Add at paused playhead writes the selected channel or an explicitly selected whole group. FK key defaults and absent-channel values use the shared authored pose before IK, so saving unchanged FK values does not bake the solver twice. Capture Pose deliberately retains the solved pose and applies it with IK mix disabled at that frame. Sparse-key editing makes channel removal explicit through the shared `replaceKeyframe:true` single-stage mutation, avoiding an intermediate deleted row. Numeric Move whole key uses shared `move_keyframe` / `move_ik_keyframe` operations in one exact-revision transaction: the row's sparse channels, named easing and Bézier controls are preserved, and occupied destinations are rejected. Delete removes the whole selected sparse row, with project undo available. This checkpoint supplies timing lanes and numeric moves; it does not claim draggable key retiming or a per-channel value-curve graph.

## Bind weight brush

`EditorRigWeightDialog` hosts an explicit bind mode of `EditorRig2DView`. It asynchronously loads the actual registered still through the same bounded, EXIF-oriented `StreamingBitmapLoader` used by native monitoring/export, at a 1024-pixel edge budget. Source dimensions are required. The displayed artwork, selected bone, rest mesh and committed influence heatmap use bind source UV; posed monitor coordinates, clip motion, authored crops and effect-stack geometry do not become brush coordinates.

The brush has a bone picker, radius in source-image-height units, signed strength, smooth/linear/hard falloff, numeric values, two-finger zoom/pan and Fit. A stroke records at most 256 spatially sampled UV dabs; reaching that bound or leaving the artwork visibly stops the draft stroke. Adding a second finger cancels the draft stroke for navigation. During a gesture, the canvas distinguishes the draft brush trail from committed weights. Release sends one immutable points batch to shared `AnimationRigEdits.paintWeights` and one captured-revision store transaction. The shared algorithm preserves normalized bindings, caps influences and returns the actual changed-vertex receipt. Unchanged strokes report the reason without producing a graph edit. Successful commits redraw current weights and preserve the viewport.

Stale or failed strokes retain the saved weights; conflicts disable the old canvas until reopening. Project undo uses its captured revision. Decoder completion owns its bitmap even after dialog/Activity closure, including rejected UI posts; accepted decode futures are not cancelled in a way that loses an allocated result. Decor detachment and dismissal share idempotent cleanup. A successful store edit is reported as saved even if later UI copying or redrawing fails, and the disabled canvas asks the owner to reopen. Brush settings/viewport are local to the open dialog, and an unreleased stroke is not persisted across Activity/process recreation. Region painting is whole-image mesh weight editing; it does not extract artwork parts or paint posed-space vertices.

## Paths and timing curves

The native motion path editor has editable anchors and incoming/outgoing tangent handles, normalized point timing, add/remove points, add/replace mode, tangent orientation and rotation offset. Draft gestures are previewed in its path canvas; Save commits the canonical `ProjectMotionPathEdits` payload. Transform, camera and audio easing controls expose named curves and editable cubic Bézier handles/numeric values. Per-key curves persist their four controls; choosing a named curve removes obsolete controls. Removing visual effects from an audio lane retains both audio default curves and per-key Bézier controls, together with gain and extraction provenance.

## Drawing and exposure sheets

`EditorCelDrawingDialog` supplies the actual vector-stroke drawing surface, raster preview, brush/eraser, color/width, stroke undo, zoom, retained bounded drafts and previous/next cel onion skins. The MainActivity hook captures programme placement, lane and revision, then calls `AnimationCelFactory` on the owner media worker. Raster publication and graph commit use one stable request key. The draft is discarded only after successful commit. A failure retains the drawing draft for reopening.

New cels are immutable generated PNG sources in the project workspace. Redrawing creates a new immutable generation; the earlier source remains available to undo and other exposures. The factory's atomic redraw overload also applies a changed hold frame count at the same expected revision. Exposure-sheet controls seek, redraw, draw the next cel, change holds, duplicate or delete the selected exposure through `AnimationCelEdits`. Off-grid timing changes are reported rather than silently pretending they remain frame aligned.

Native output cadence choices are integer 12, 24, 30 and 60 fps. A legacy project retains its 30 fps output until explicit cadence selection or its first cel chooses a supported cadence. Cel timing uses cumulatively rounded frame boundaries on the existing integer-millisecond graph. Programme frame stepping uses cumulative boundaries for the chosen output cadence. Changing output cadence does not retime existing artwork. New placement after an exposure from a different cadence is quantized at or after its actual end. Fractional encoding cadence is unavailable.

## Remaining engineering scope

The source additions do not establish device or rendered-output correctness. When implementation is ready and verification is authorized, inspect preview/export parity, actual encoded frame timestamps, rig bind identity/deformation/IK, sparse key retiming and replacement, EXIF-oriented brush coordinates, brush collision/undo behavior, cubic timing, immutable redraw history and revision conflicts. The broader industry animation direction still includes draggable key retiming and per-channel value curves, reusable cross-project rig libraries, artwork part/layer management, vector path authoring beyond strokes, and additional constraint types. Those controls are not advertised as implemented by this checkpoint.
