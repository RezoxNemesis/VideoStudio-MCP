# Cinematic source animation native MCP contract (3.7.2)

This is an additive native application-v3 contract on the existing `/app-mcp-v3/` endpoint. It does not change MCP SDK protocol negotiation, bind a ChatGPT account, deploy the Worker, or establish that an updated phone is connected. New actions reject old/unknown native app versions before queue admission.

`app_storyboard_series_plan` describes literal ordered owned anchors and missing annotations without allocating a project or heavy job. `app_storyboard_artwork_preflight` additionally captures original image SHA-256, coded/oriented geometry and EXIF orientation for annotation authoring. `app_storyboard_series_audit` admits the provider before queueing a pixel audit. `app_animate_storyboard_series` queues a fresh separate film only after source/provider admission. All use `sourceProjectId`; default `motionIntent` is `cinematic_action`.

Cinematic action requires source-byte-bound black and white profiles for both endpoints, sixteen authentic source joints, actor outlines, original sword hilt/tip/outline, explicitly authored contact arrays and one exact choreography beat per ordered shot. Cinematic action requires at least one explicitly authored ground-contact interval per actor. Empty arrays are retained only as incomplete drafts or explicit source deformation; a future airborne contract must be explicit. No stance is inferred. Missing authentic provider data returns `INSUFFICIENT_MOTION_PROVIDER` before an output/heavy job is created. Unreachable authored plants are evaluated on output phases and authored interval boundaries/interiors before admission. No hidden-limb model, motion diffusion executor, automatic weapon annotation or substitute procedural sword is available.

Explicit `source_deformation` and `environmental` have limited source deformation/scene scope. They do not certify convincing action. Non-rig sources use verified oriented contain-fit pixels; rig coordinates require a common exact oriented aspect. Output dimensions are even 256..1280 with at most 720×1280 pixels, in either orientation. Omitted dimensions derive an exact bounded source aspect where possible; incompatible source registration fails clearly.

Source selection is literal `assetIds` (2..160 ordered occurrences, including repeats), or ordered `anchorGroups` that explicitly group cross-format variants and cover the original image library. Filenames and byte aliases do not erase beats. `sourceRigBindings` is an array of `{assetId,blackRigId,whiteRigId,blackRigSha256?,whiteRigSha256?}`. `contactPlans` and `choreography` are ordered transitions with `shotIndex/fromAssetId/toAssetId`; a repeated asset pair can have different contacts and beats. Contacts contain `{black:[{foot,start,end,anchor}],white:[...]}`; foot is `leadingFoot|trailingFoot`, phase 0..1, anchor original oriented image `[u,v]`. Optional sourceWidth/Height must match accepted original geometry.

The twelve beats are STANDOFF, BLACK_STEP, WHITE_ADVANCE, CHARGE, DUAL_CHARGE, PRE_IMPACT, CLASH, BLADE_LOCK, FOLLOW_THROUGH, WHITE_KNOCKBACK, BLACK_LANDING and AFTERMATH_RECOVERY. Each beat controls independent actor pacing between authored endpoints; it does not infer missing poses or establish decoded motion quality.

`app_save_source_rig_profile` uses `projectId/sourceAssetId/sourceProjectUpdatedAt`, optional `rigId/expectedRigSha256`, boolean `black`, a sixteen-pair `joints` array, body/weapon geometry and the displayed original `sourceSha256`. Joint order is pelvis,chest,neck,head,swordShoulder,swordElbow,swordHand,freeShoulder,freeElbow,freeHand,leadingHip,leadingKnee,leadingFoot,trailingHip,trailingKnee,trailingFoot. Legacy profiles without original-byte hashes remain readable and cinematic-ineligible. `app_list_source_rig_profiles` returns full definitions and SHA digests in pages (`offset`, `limit` 1..8, nextOffset), with a 192 KiB response-page budget. Existing native annotation capacity is 100 profiles per project.

`app_storyboard_program_save/get` uses the same private ordered program store as the phone editor. Save requires a source revision and optional expected program SHA. The program carries literal sourceAssetIds, a map of exact sourceRigBindings with both profile SHA digests, ordered contacts and choreography. Render may supply `programId/expectedProgramSha256`; native code resolves the authoritative saved annotations and verifies sources/profile hashes before admission. Human launch uses the same action and programme identity. Explicit get editOnly:true opens retained stale draft metadata (renderReady:false/sourceBytesVerified:false) for review; default get and all render/recovery paths remain strict. A two-anchor explicit duration preserves ceil(fps×seconds) output frames; the legacy generic ADVANCE/etc wrapper returns structured missing_program instead of silently choosing a choreography. Exact output source:WxH registration is retained through export.

Caller underscore fields are stripped at Worker and native command boundaries. Native recovery reads its actual durable ledger, reuses the accepted source manifest/profile/contact/beat proof and exact output timestamp, and validates those proofs before touching a partial graph. Caller outputProjectId is rejected. Missing legacy proof or a changed source, profile, programme or partial target blocks recovery and preserves old generations. Generation directories are immutable; source files and earlier generation files are not deleted. Each generation carries a bounded fsynced admission.json containing only its source manifest and admission proof; per-frame metadata records the sidecar SHA, source hashes and shot index. Folder-scoped project archiving preserves these JSON proof files. Each saved output revision is checkpointed; a crash between graph save and checkpoint conservatively blocks cleanup rather than assuming ownership.

Public storyboard metadata is limited to 64 KiB and depth 64; native captured manifest and compact semantic plan have separate 256 KiB budgets. Originals are bounded at 160 images, 32 MiB each and 512 MiB aggregate for this pipeline. Native application-v3 commands/results now use checksummed immutable 64 KiB chunks with a versioned manifest and atomic ledger migration. Accepted pending work is never pruned; bounded terminal compaction keeps original status/result SHA proof and explicitly reports resultExpired when full bytes have expired. Limits are 160 commands, 2 MiB each request/result and 16 MiB total JSON; retained compact receipts are bounded to 160 rows / 64 KiB. Device registration metadata is independently chunked up to 2 MiB, preserving exact projects and stable owner identity. Sequence updates, leases, ACKs and alias queue merges share storage transactions. Native polling bounds the hydrated reply to 3 MiB before taking any leases, preserving sequence order and leaving remaining rows pending.

Large native programme/plan/render results return a summary and bounded JSON fragments through app_get_command_result_page (or hybrid_get_command_result_page). Ordered fragments reconstruct the entire credential-redacted view: nested credential, private handoff URL and inline base64 fields are removed from result text, while contact sheets remain available as image content. viewSha256 validates exact reconstructed view bytes, while canonicalResultSha256 identifies the immutable original receipt, which redaction does not modify. Each fragment is at most 32 KiB; results are never silently truncated. Status summaries omit oversized scalar fields with explicit summaryPartial/omittedSummaryFields; the full permitted value remains retrievable in result pages. Inline media compatibility is honestly bounded to 1 MiB decoded so a single command fits native polling; larger explicit originals use private direct HTTPS/attachment handoff. No live host capability is assumed.

Native command admission revalidates the current registered identity, owner index, compatibility/version requirements, pause state and permission mode inside the same transaction that writes the sequence and queue. A superseded device snapshot or revoked hybrid binding rejects before acceptance; the caller can retry the current binding. Hybrid resolution follows the proven owner index after an alias migration and cannot overwrite a concurrent revocation with an older binding snapshot.

Pixel temporal/retention checks remain separate from cinematic QA. Manual rigs and scene recipes have no invented segmentation-confidence score. Missing decoded physical metrics are `UNAVAILABLE/INCOMPLETE`; every completion retains `cinematicAcceptance:false`. Foley may follow the first intended native blade-contact event at its exact generated frame PTS, with `PREDICTED_NATIVE_EVALUATOR` origin and synthesized PCM event-stem receipts. This is not decoded MP4 collision/audio synchronization proof. Generated 24/30/60 FPS frame holds use cumulative rational timing and explicit rational-authored-v1/frameIndex tags for native encoder cadence; decoded encoder cadence still requires actual output inspection.

Regression sources cover native rejection before allocation/job, frozen profile replay/change, legacy source-hash ineligibility, changed batch segmentation, and Worker actual typed-handler/version/schema/metadata/privacy admission. The root orchestrator runs the selected tests/builds. Real Test 1 originals, owner-authenticated ChatGPT/native connection, installed-phone render, decoded cinematic QA and any cloud neural executor remain separate prerequisites; source/unit evidence does not claim those outcomes.

The supplemental nine-frame reference ZIP was inspected in the private engineering workspace: source order, all original hashes and 864×1536 dimensions match its manifest, while the `.png`-named originals are actually JPEG-encoded. They remain unchanged. The 8-second/24-FPS reference is separate from source art. This workspace inspection does not import files into the installed native app or produce an accepted cinematic film.
