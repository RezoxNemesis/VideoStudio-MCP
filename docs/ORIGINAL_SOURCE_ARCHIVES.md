# Original-source archives

`app_archive_source_media` / `archive_source_media` act on one explicit project and registered original-source asset. Android captures the exact source metadata and accepted revision in an owner-bound SQLite pin, captures the selected SAF tree grant, and streams source bytes in 256 MiB chunks through a 256 KiB buffer. Upload journals retain chunk sizes and SHA-256 hashes. Remote readback, a complete unchanged-source pass, verified manifest, and a final commit marker govern the committed receipt. The implementation limit is 64 GiB per source; provider quota remains unknown.

`app_restore_source_media` / `restore_source_media` require an exact committed generation. Restore verifies every chunk and whole-source hash into an immutable app-private copy. Recovery verifies an existing completed copy by its full hash before reuse. Native relink uses the accepted revision and normal source-kind, handle, track-lock and portrait protections. When relink is blocked, the inspected verified copy is registered in the owned Media Bin without inserting a timeline clip; the receipt says `relinked:false` and records the conflict. Original provider media remains intact.

The owner service intent is `ACTION_LOCAL_SOURCE_MEDIA` with `operation` (`archive` or `restore`), `projectId`, `assetId`, `expectedRevision`, `requestId` (UUID), `storageTreeUri`, and restore `generationId`. Transfers use the shared owner-priority heavy lane. Per-request and per-asset progress receipts are retained in bounded preferences; actual archive/restore results also persist in the durable recovery ledger and source-vault catalog. `app_source_media_status` reads local catalogs/journals and performs no remote scan.

`ACTION_CANCEL_LOCAL_SOURCE_MEDIA` stops only the matching owner session and retains its journal/pin. Explicit owner resume uses the same UUID and `resume:true`, after `resumeReady` becomes true. Cancelled work never resumes automatically. `ACTION_FORGET_LOCAL_SOURCE_MEDIA` requires a cancelled session and stopped worker (`forgetReady`). It discards only the exact retained local journal/reference/pin and cancelled recovery plan. Original media, copied media, committed catalogs, remote archives and remote draft chunks remain. Forget requires no provider access, so it can release a request whose folder grant was lost.

Source transfer, restart, provider failure and large-file behavior have been reviewed in source. Tests, builds, Android execution, provider transfers and live ChatGPT verification remain deferred; no runtime success is asserted here.
