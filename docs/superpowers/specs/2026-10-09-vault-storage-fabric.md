# Vault storage fabric

The approved continuity bundle requires five owner-connected profiles, 256 MiB–1 GiB checksummed chunks, distribution and replication across authorized locations, resumable transfers and preserved originals. Build on existing five SAF profiles and production local Vault. Direct provider OAuth remains a separate dependency; label this folder-scoped document-provider storage accurately.

Create a chunk replication engine consuming an already complete project-owned Vault manifest. A document-tree blob adapter writes only into an app-managed VideoStudioVault namespace inside an explicitly connected profile. Its API streams put/open/delete and returns provider URIs; a fake file-backed adapter is used only in tests. The engine hashes source and remote bytes, persists an upload token and pending intent before creating a remote document, then publishes verified location state in SQLite only after verification, rechecks indexed replicas before reuse, and resumes remaining copies after interruption. A completed replication requires a verified replica of every chunk plus a verified binary manifest on every participating profile. Copies can be spread round-robin, with 1–5 replicas across distinct selected profiles; deduplicated identical objects copy once per profile. Actual reported free quotas constrain allocation; unknown quotas stay unknown. Originals/local Vault objects are retained.

Expose the same job through owner media-bin controls and MCP vault_replicate(projectId,assetId,profileIds,replicas). The owner selects connected profiles and replica count. MCP cannot connect new folders, accept arbitrary content URIs, or access unselected media. Jobs persist parameters and checkpoints, enforce STOP and scope, and expose verified locations/status through vault_inspect. Never mark queued work completed. Network/file provider errors remain recoverable failures. No auto-eviction or deletion of originals.

Tests use real local Vault objects and SQLite with file-backed remote adapters to check cross-profile distribution, all byte hashes, deduplication, restart reuse, corruption detection, cancellation, quota refusal and source binding. Add Android compilation/unit CI; actual third-party provider/network/device verification remains explicit pending evidence until such accounts are connected.

Review hardening: recover the token-named pending/final document after process death; retain indexed locations on temporary provider failures; overwrite confirmed corrupt app-managed documents in place rather than allocating quota-consuming replacements. Replica database v2 adds token/state without discarding v1 locations. Project-bound discovery returns connected IDs/labels/real quota while withholding tree capabilities and private project pins.
