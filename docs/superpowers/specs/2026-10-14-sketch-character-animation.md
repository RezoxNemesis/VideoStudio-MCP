# Prepared-sketch 2D character animation

The user authorizes autonomous implementation and workspace tests. Success requires actual articulated action from prepared drawings, about100 continuous coloured frames, dialogue, several views including a drawn POV, playable output and screenshots. Human and ChatGPT controls use the same native operations. The original sketches remain unchanged.

Use the existing SketchDocument and SketchFrameRenderer rather than a second demonstration renderer. A deterministic compiler accepts a prepared drawing and videostudio.sketch-animation.v1 program: named parented joints in canvas coordinates, source-object bindings, local rotation/root pose keys, linear/smooth/hold timing, two-bone IK contact intervals, camera keys/layer selection, dialogue and mouth/cel intervals. Rigid attachments include independently prepared transparent raster parts; weighted point deformation is for vector geometry. A flattened image does not become an articulated character automatically.

Output is a separate editable standard sketch document with source fingerprints and a quantitative motion report. No opaque generated image replaces the drawings. Existing4MiB/4096object/131072point/4096key/1200frame limits remain bounded, with explicit budget failures. Every dependency is hash verified and copied before output publication; frozen source snapshots preserve deterministic results after human edits. Operation IDs and revision checks prevent duplicate or destructive saves/bakes.

The human activity shows the prepared sketch, draggable joint poses, part bindings, frame/pose timing, contacts, camera and dialogue controls. Preview uses the shared compiler and renderer away from the UI thread. The agent save/get/list/bake actions expose the same data and renderable outputs through the existing app_execute bridge and independent mailbox.

The workspace film is original native vector artwork: a teal/coral courier, rooftop drone encounter, anticipation/deflection/contact/recovery, wide/POV/medium views, dialogue with expression changes. Render exactly100frames at24FPS with Android Canvas under Robolectric native graphics. Encoding those exact PNGs with workspace FFmpeg is labelled workspace encoding, never phone export. Check articulated joint changes independently of camera, bone lengths, foot-contact error, frame order/count, colour/identity continuity, dialogue ranges and cut placement. A moving pixel or passing encoder is not cinematic acceptance; visually inspect actual frames and movie, refine concrete flaws.

Phone installation and native device export remain separate verification stages. Preserve original package/signing identity, projects, keys and the no-Gallery boundary. No commercial generation API or new cloud credential is required for this feature.
