# Video studio 4.0 design

The owner asks for an installable APK containing the earlier fixes, the visible name "Video studio", a minimal touch interface and a connection usable by sharing one app key. They authorize autonomous implementation and accept starting without old relay history. This does not require clearing phone projects or changing the signer. The source starts at PR73/b84922a; use the existing workspace and preserve all earlier features.

The visual design uses charcoal #111318, surfaces #1B1E25/#242832, warm text #F5F5F1, muted #9BA3AF, mint accent #A7F3D0 and border #343944. Shared native components use48dp minimum touch height and restrained rounded surfaces. Home emphasizes creating/importing and a searchable studio/tools directory. Editor keeps preview/timeline foremost. Sketch Studio puts its canvas first, with compact essential controls and grouped menus for files, brush/text, layers, cels and workspace. Existing human and live-agent operations remain reachable. No new heavy UI framework is needed.

The existing private MCP stays available. Add an encrypted GitHub mailbox using the owner's already accessible public RezoxNemesis/VideoStudio-MCP repository and a dedicated videostudio-agent-mailbox branch. No hosting account/new MCP connector is required for this delivery route in clients that have GitHub write access. An app key "vsapp1." plus the existing device-owned owner key is shared explicitly from Android; it is never compiled into the APK or published. Fresh installs generate their own key normally. Encryption derives AES256-GCM and a public routing channel through HMAC-SHA256; raw commands/references remain private even though the carrier repository is public.

Packet contract: schema videostudio.agent.packet.v1, channel=first32hex HMAC(owner,"VideoStudio agent channel v1"), key=HMAC(owner,"VideoStudio agent encryption v1"), AAD="videostudio.agent.packet.v1:"+channel,12byte random nonce, ciphertext includes16byte GCM tag, all binary fields base64url. Plaintext schema videostudio.agent.commands.v1, packetId UUID, issuedAtMs/expiresAtMs (maximum7days, maximum5minutes clock lead), commands1..128 with stable UUID id, action and object parameters. Maximum plaintext2MiB/outer3MiB; individual parameters512KiB. Authentication, timing, structure and every command are validated before any execution. Immutable GitHub path mailbox/<channel>/<packetId>.vscmd, discovered through a CAS-updated index.json containing at most4096 ordered packet IDs. Native polling uses only the fixed owned repository/branch, no redirect of the owner secret; received packets are encrypted private files and execution enters the existing ControlService. Respect pause, native privacy, cancellation and journal idempotency. Never blindly repeat uncertain side effects with a fresh command ID.

Receipt contract: schema videostudio.agent.receipt-envelope.v1, channel, commandId, nonce,ciphertext; AES-GCM AAD="videostudio.agent.receipt.v1:"+channel+":"+commandId. Plaintext preserves actual command status/result; job admission is distinct from terminal execution. Large results remain complete, up to2MiB plain. Private persisted receipts are published through VideoStudio's existing direct device-metadata API, not its broken native command-array store: deviceId vsm_<channel>_<UUIDwithoutdashes>_p<index>, capabilities["videostudio.agent.receipt-carrier.v1",JSONpage], each page has commandId,index,total,receiptSha256,fragment (32KiB ASCII maximum). Readers concatenate and verify the complete SHA256 and GCM proof. Native offline receipts retry without blocking newer ones. A full Cloudflare outage delays remote receipt visibility; independent GitHub delivery and local execution/journal continue. Report that boundary explicitly; this is independent task delivery, not a fabricated independent all-provider two-way service. Google Drive remains scoped native storage, not a compute substitute.

The sender/helper takes an app-key file (or the already supplied private endpoint file), action/parameters and optional existing command ID. It creates immutable encrypted commands and publishes only ciphertext; logs omit key/owner URL/media. Status can retrieve the separately paged encrypted receipts without MCP tool admission. ChatGPT can use this helper through existing GitHub/terminal capabilities; an account with no GitHub writing capability has no automatic delivery authority. App UI includes Share app key, connection status and retained backup receipt access.
